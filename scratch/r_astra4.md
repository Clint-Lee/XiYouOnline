## 结论

建议采用 **1 张新地图、8 个阶段、1 场水府探战、1 场鼍洁首领战、1 个章节奖励键**，闭环到 `heishui_cleared`。

核心叙事是 **识破摆渡骗局 → 寻访失府河神 → 探明水府 → 请来摩昂 → 制服鼍洁 → 救人复府渡河**。不新增潜水、护送、援军召唤或跨地图通信系统。

两项口径先统一：

- **西海龙王应为敖闰，敖顺是北海龙王**；摩昂为西海龙王之子、鼍龙表兄，相关对白统一修正。
- 本方案沿用项目给定的首领名“鼍洁”；不把这个专名视为原著校勘结论。

**设计取舍：**终态仍由唐僧承接唯一金色感叹号，避免把“传送门也是任务 NPC”变成额外改造；后续章节接入时再替换这个目标。

### 1.2 阶段推进规则

1. **首次入图守卫**  
   仅当当前阶段恰为 `huoyun_cleared` 时初始化 `heishui_arrived`；重复入图、已完成本章或进入后续章节时均不回退。

2. **战斗推进不依赖延时对白**  
   胜利回调先持久化下一阶段，再调用 `scheduleStoryDialogue`。离图导致对白取消，不能导致阶段丢失或必须重打。

3. **关键事实有补读入口**  
   探战后的身份线索可由河神重述；首领战后的救人复府可由复位河神重述，不依赖某一次弹窗成功播放。

4. **失败不抹掉进展**  
   探战失败停留 `heishui_scout_ready`；首领失败停留 `heishui_boss_ready`。重试建立新的敌人实例，清空上场机制状态。

### 1.3 必须同步的阶段设施

八个阶段必须一次性同步到：

- `phaseWeights`：紧接火云洞阶段，保持严格递增；具体数值查现有表后确定，不凭空指定。
- `isNpcVisibleInStoryPhase`：章节 NPC 使用明确阶段集合控制，不能仅用 `>=`，否则船夫、守将、鼍洁会长期残留。
- `MAIN_QUEST_TARGETS`：逐阶段配置一个目标。
- `getOrdealAndQuestInfo`：逐阶段配置目标动作及失败／满包后的提示。
- `minimap.getCurrentQuestTarget`：目标实体 ID 与主线表完全一致，位置跟随实体实际落点。

### 1.4 对白与奖励约定

建议对白键：

| 用途 | 对白键 |

## 3. Boss 机制：鼍洁

### 3.1 机制名与核心张力

**机制名：黑水换甲。**

鼍洁以黑水护体，在两种防护之间切换：

| 姿态 | 效果 | 玩家读法 |
|---|---|---|
| 凝鳞 | 提高物理防御，法术防御保持正常 | 鳞甲紧合，宜以法术攻之 |
| 散流 | 提高法术防御，物理防御保持正常 | 水幕流转，宜近身破之 |

每完成 **2 次自身有效行动**后切换一次；失去行动不计数。开场固定为凝鳞，让首次接触可学习。

**张力来自伤害类型选择和法力分配，不是倒计时大招。**不设蓄力、爆发或恢复窗口，也不增加即死惩罚。

### 3.2 两种应对

1. **跟随姿态切换攻击类型**  
   凝鳞时使用现有法术伤害技能，散流时使用普攻或物理技能，以较低回合成本击败首领。

2. **采用物理保守打法**  
   不要求特定法术或新道具，持续普攻仍能造成有效伤害，在散流阶段获得正常输出；代价是战斗变长、承受更多常规攻击。

抗性不能设为免疫。具体防御增量必须用现有伤害公式校准，确保同级、无额外法术资源的玩家仍有胜算。

### 3.3 buff 承载

- `mechanicId` 建议为 `heishui_current_armor`。
- `mechanicConfig` 声明起始姿态、切换行动数、两种防护增量。
- `enemy.buffs` 中只保留一个该机制状态，记录：
  - 当前姿态；
  - 当前姿态已完成的有效行动数；
  - 用于伤害结算的防御修正。
- 防御修正从基础属性计算，不能反复直接增加 `enemy.def`／`enemy.mdef`，避免重试与切换造成永久叠加。
- 复用现有机制调度入口；**不要同时启用“行动计数”和通用 buff 到期自动换态两套计时**。

首领对象仍须提供题设中的完整战斗字段；`appearance`、`modelId`、`skills` 均引用真实存在的资源或配置。

### 3.4 失败后果与反馈

- 攻击类型不匹配：伤害降低，同时给出对应提示，如“凝鳞抵住了部分兵刃伤害”。
- 姿态切换：明确显示新姿态及适合的攻击类型，不只用颜色区分。
- 战败：沿用现有败北处理，不增加永久损失，阶段保留 `heishui_boss_ready`。
- 摩昂的擒拿放在胜利对白中完成；战斗目标解释为“破其水势、创造擒拿机会”，不伪装成已经实现的援军参战系统。

**优先级判断：**该机制可后置；基础版先用普通首领战打通章节闭环。

## 4. 三条禁笑区与幽默位

### 4.1 三条禁笑区

| 禁区 | 本章必须严肃处理的内容 |
|---|---|
| 不拿受害者遭遇开玩笑 | 河神被夺府、被迫流落；不写成“没本事守家”的笑柄 |
| 不拿囚禁／伤亡当笑料 | 唐僧与八戒被摄走、等待获救；不安排狱中插科打诨淡化危险 |
| 主角不承担连续逗嘴 | 悟空识破局势、沙僧探水府、摩昂擒妖均以行动推进，不每段对白安排包袱 |

鼍洁的亲缘关系用于解释管束与问责，不能写成“有亲戚就不用担责”。摩昂押回问罪必须明确。

### 4.2 合适的两处幽默位

**位置一：开场询问船资，危险显露之前。**

- 来源：船夫伪装普通营生，却不自觉摆出神府主人的口气。
- 示例：“这河上……咳，这船上，自然听我的。”
- 作用：轻微失言兼伏笔，不让主角显得故意忽视明显危险。
- 妖怪现形后立即收住幽默。

**位置二：救人复府、正式交接之后。**

- 来源：鼍洁先前自封的夸大头衔，被摩昂平静纠正。
- 示例：“‘黑水大王’不必报了，报本名。”
- 作用：讽刺僭越与虚荣，不嘲弄俘虏处境；一句结束，不发展成连续斗嘴。

## 5. Node 断言清单

建议新增 **14 组断言意图**，保留现有 1883 条基线；新增后总数应高于 1883。

1. **前章衔接与不回退**  
   `huoyun_cleared` 首次入图进入 `heishui_arrived`；未达门槛不能启动；重复进入及后续章节回访不会重置。

2. **阶段链合法性与权重顺序**  
   八阶段按规定递增；正常触发可到终态；错误阶段调用推进动作不能跳阶段。

3. **对白引用完整性**  
   所有直接调用及 `scheduleStoryDialogue` 引用的键均存在；选项的 `nextStep` 与动作引用有效。

4. **战后对白时效性**  
   延迟期间换地图或换阶段，旧对白不弹；即使对白取消，已保存的胜利进度仍保留。

5. **奖励幂等**  
   连续点击、重复交互及读档重试后，物品、经验、银两和加成仅发放一次；`already_claimed` 不产生额外收益。

6. **满包失败与重试完整性**  
   返回 `inventory_full` 时无部分发奖、无已领取标记、阶段不变；河神和领取入口保留，腾出空间后可完成。

7. **地图尺寸与可行走比例**  
   尺寸为 42×30，可行走比例处于 42%—46%；比例基于实际碰撞格，而非装饰图层。

8. **地图 BFS 与闭环保留**  
   从出生点四向 BFS 可达全部可行走格及关键交互邻格；至少保留经北道、经旧庙南道两条通往神府的路线。

9. **实体落点与传送有效性**  
   各阶段实体不越界、不落墙、不非法重叠；全部已启用传送门都有合法目标；后续出口未接入时不会执行传送。

10. **NPC 显隐矩阵**  
    船夫现形后消失；被俘期间唐僧、八戒不可见；两种河神实例及两组师徒实例互斥；鼍洁战败后不可重新挑战。

11. **金色感叹号唯一性**  
    八个阶段分别恰有一个有效主线目标，该实体可见且可交互；满包状态仍唯一指向复位河神。

12. **小地图与任务卷轴一致性**  
    小地图目标 ID、实际坐标与主线表一致；卷轴动作对应当前目标，终态无“继续挑战鼍洁”等过期文案。

13. **战斗入口与回调守卫**  
    探战、首领战只在各自阶段启动；重复交互不能并发开战；完整敌人字段合法；败北不推进，重复胜利回调不二次推进或发奖。

14. **开幕与可选机制回归**  
    章节开幕配置指向正确地图及阶段，副标题七字、印章四字；若加入换甲机制，验证两次有效行动换态、不叠加基础属性、重新开战状态归零，并保留红孩儿机制原有断言。

## 6. 实施顺序

### 第一步：审查既有接口与确定命名

核对：

- `phaseWeights` 后续阶段的取值范围。
- 地图 `region` 的合法值、NPC 占格与交互距离规则。
- 前章出口的真实位置及传送配置。
- 已有水族资源、技能、伤害公式、机制调度钩子。
- `claimStoryReward` 的实际原子性及满包行为。
- `node test_suite.js` 确认原有 **1883/1883** 仍全绿。

**产物：**实体 ID、阶段、对白键、奖励键、地图连接口径定稿。

### 第二步：完成地图与实体骨架

先做 `heishuihe` 的碰撞格、闭环路线、出生点、前章连接及各阶段实体落点。

**必须同批完成：**地图注册、碰撞数据、实体坐标、BFS／比例断言、传送目标校验。  
不能先放传送门，再等待目标地图补注册。

### 第三步：完成阶段契约与对白

一次性接入：

- 四张阶段设施；
- `minimap.getCurrentQuestTarget`；
- 八阶段推进守卫；
- 全部对白键及其动作；
- 章节开幕配置。

开幕建议：

| 字段 | 值 |
|---|---|
| `id` | `chapter_13` |
| `chapterNum` | `13` |
| `title` | 黑水河 |
| `subtitle` | 黑水擒僧龙子来 |
| `seal` | 黑水伏鼍 |
| `triggerMap` | `heishuihe` |
| `triggerPhase` | `heishui_arrived` |

**必须同批完成：**阶段声明、NPC 显隐、主线目标、卷轴、小地图目标及被引用的对白键。避免出现“阶段已推进，但没有人可交任务”。

### 第四步：打通战斗与奖励闭环

接入探战、普通版鼍洁战、胜败回调、救人复府、奖励领取和满包重试。

**必须同批完成：**

- 战斗入口阶段守卫与重复启动保护；
- 胜利推进、败北保留、延时对白双校验；
- 奖励领取、失败保留入口、已领取状态修复；
- `heishui_cleared` 与渡河尾声。

完成后应能从 `huoyun_cleared` 连续玩到 `heishui_cleared`，且不依赖后续章节。

### 第五步：加入可选机制与表现

可后置：

- 黑水换甲机制及对应测试；
- 水色、浪纹、神府装饰；
- 非主线野怪和环境对白；
- 两处克制的幽默；
- 后续章节地图及出口对接。

**不可后置：**目标唯一性、满包重试、对白键存在性、BFS 连通和阶段守卫。

### 第六步：回归与验收

除自动测试外，至少走通四条人工路径：

1. 正常游玩完整通关。
2. 两场战斗分别失败后重试。
3. 奖励满包失败，整理背包后领取。
4. 战后立即离图、重进或读档，仍可继续。

**验收底线：旧测试全部保留、新测试全部通过；任何阶段都明确“找谁、做什么、失败后如何继续”。**
